The Late-Night Rush DAG

Solo build · Submit a .py file

Scenario

A restaurant wants an Airflow DAG that kicks off their late-night rush prep — checking expected demand, deciding how much staff to call in, and always closing out with a shift report, even if something along the way fails.

Requirements

  • DAG id: late_night_rush. Must be timezone-aware (use pendulum, not plain datetime), scheduled daily at 11 PM IST, and must not backfill historical days.
  • First task, check_delivery_demand, simulates a call to a delivery-aggregator API. Configure it with retries=3, an initial retry_delay of 1 minute, exponential backoff enabled, and a max_retry_delay capped at 10 minutes.
  • Based on the (simulated) demand value, branch using BranchPythonOperator: high demand goes to a call_extra_staff path, otherwise a standard_staffing path. (Branch on an actual value returned by the check — not a string-matching shortcut.)
  • Both paths must converge into one final task, shift_report, which should run regardless of which branch was taken — pick the correct trigger_rule so it doesn't get skipped the way close_kitchen did in class.
  • Attach an on_failure_callback via default_args (a simple function that logs/prints the failing dag_id and task_id is enough — no real Slack/email integration required) so it covers every task in the DAG automatically.

Submit

  • One .py file, named late_night_rush_dag.py
  • A short paragraph (3–5 sentences): if this DAG had been left paused for a week with catchup=True instead of False, what would happen the moment you unpaused it — and why?
This combines five separate things from today — timezone-aware scheduling, retry/backoff config, branching, trigger rules, and failure callbacks — into one working DAG. Get each piece running on its own first before wiring them together.
